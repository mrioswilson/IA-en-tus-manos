      Abre un poco más la caja: cómo leer los datos

      · = espacio; ↵ = salto de línea; ⇥ = tabulación. Se muestra el texto original en la ficha de cada token. Un porcentaje es la probabilidad nativa × 100. En vivo, la distribución original se obtiene del muestreador a T=1 sin filtros; la ajustada usa la temperatura elegida. El respaldo conserva exp(logprob) de Ollama. Las barras usan una escala absoluta de 0 a 100 %. No redistribuimos la masa de los tokens que faltan. «Otras posibilidades» incluye todo lo que queda fuera de las barras visibles.

      En vivo se conservan los IDs y bytes que informa llama.cpp. Las grabaciones anteriores conservan los bytes informados por Ollama. El texto se vuelve a tokenizar después de cada elección manual. Los tokens especiales o con UTF-8 incompleto se muestran, pero no se añaden manualmente. Una semilla fija facilita repetir una consulta en el mismo entorno; no garantiza resultados idénticos entre versiones, hardware o estados de caché.

      El archivo «Guardar experimento» conserva solicitudes, respuestas originales, hashes, IDs, bytes y decisiones. La respuesta base de todo el vocabulario se comprime sin pérdidas con gzip/base64 para auditoría. Los datos se mantienen en esta pestaña hasta guardarlos o usar «Reiniciar». El servidor no guarda sesiones.
